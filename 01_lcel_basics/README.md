# Модуль 01. Основы LCEL: сборка цепочек через оператор «|»

> LCEL (язык выражений LangChain) позволяет описать целый конвейер обработки одной строкой: `prompt | llm | parser`.

---

## 1. Зачем нужен этот модуль

Без LCEL один запрос к нейросети приходится делать вручную в четыре действия: взять шаблон, подставить значения, вызвать модель, вытащить текст из ответа. Каждое действие отдельно, и данные нужно переносить из шага в шаг самому.

LCEL собирает эти действия в одну цепочку. Вы описываете, что откуда куда течёт, а запуск выполняет сама цепочка.

---

## 2. Объяснение для новичка

Если вы работали в терминале Linux, вы уже знаете этот принцип:

```bash
cat журнал.txt | grep ошибка | sort
```

Вывод первой команды становится вводом второй, вывод второй — вводом третьей. В LangChain то же самое, только вместо команд — части конвейера:

```text
входные данные  |  шаблон промпта  |  нейросеть  |  очиститель ответа
```

Заводской аналог: заготовка попадает на первый станок, потом на второй, потом на упаковку. Каждый станок делает одну операцию и передаёт результат дальше.

| Деталь конвейера | Что делает |
| :--- | :--- |
| Входной словарь | Подаёт «сырьё»: темы и параметры вопроса |
| Шаблон промпта | Вставляет сырьё в заготовку-вопрос |
| Нейросеть | Генерирует ответ |
| Очиститель (парсер) | Достаёт из ответа чистый текст |

---

## 3. Объяснение для профи

- Оператор `|` перегружает метод `__or__` у объектов `Runnable` и возвращает `RunnableSequence`.
- Любой компонент реализует единый интерфейс: `invoke`, `stream`, `batch`, а также асинхронные `ainvoke`, `astream`, `abatch`. Цепочка сама является `Runnable`, поэтому её можно вкладывать в другие цепочки.
- Типы данных на стыках должны совпадать: выход левого компонента обязан подходить на вход правого.
- Каждый компонент цепочки виден в трассировке LangSmith как отдельный шаг, поэтому удобно искать, где именно данные пошли не так.
- Температура задаётся в модели, а не в цепочке: её нужно подбирать под задачу.

## 5. Термины

| Термин | Простыми словами | Техническая суть |
| :--- | :--- | :--- |
| LCEL | Способ соединять детали знаком «\|» | Декларативный синтаксис сборки цепочек |
| `Runnable` | Любая деталь, которую можно запустить | Базовый интерфейс с методами `invoke`, `stream`, `batch` |
| Оператор `\|` | Передать результат дальше | Перегруженный `__or__`, создаёт `RunnableSequence` |
| `ChatPromptTemplate` | Заготовка вопроса с пропусками | Шаблон списка сообщений с переменными |
| `from_messages` | Собрать шаблон из списка реплик | Принимает пары «роль, текст» |
| Плейсхолдер `{topic}` | Пропуск в тексте | Имя переменной в фигурных скобках, значение берётся из словаря |
| Роль `system` | Инструкция «как себя вести» | Превращается в `SystemMessage` |
| Роль `human` | Вопрос человека | Превращается в `HumanMessage` |
| `StrOutputParser` | Очиститель ответа | Берёт `content` из `AIMessage` и возвращает обычную строку |
| `chain` | Готовый конвейер | Объект `RunnableSequence` |
| `temperature` | «Смелость» модели | Чем выше значение, тем разнообразнее ответы; в файле стоит 0.7 |

## 6. Кто что выполняет

| Шаг | Что происходит | Кто выполняет |
| :--- | :--- | :--- |
| 1 | Задаёт тему и область | Вы (словарь `inputs`) |
| 2 | Подставляет значения в шаблон | `ChatPromptTemplate` |
| 3 | Отправляет сообщения и получает ответ | `ChatOpenAI` |
| 4 | Достаёт из ответа чистый текст | `StrOutputParser` |
| 5 | Запускает всю цепочку одним вызовом | `chain.invoke(inputs)` |
| 6 | Печатает результат | Ваш скрипт |

---

## 7. Какие данные проходят по цепочке

```text
 dict ──► ChatPromptTemplate ──► ChatOpenAI ──► StrOutputParser ──► str
 {"topic":...,   сообщения:        AIMessage       чистая строка
  "domain":...}  система + человек
```

| Этап | Компонент | Что получает | Что отдаёт |
| :--- | :--- | :--- | :--- |
| 1 | Входные данные | — | словарь `dict` |
| 2 | `prompt` | словарь | готовые сообщения (система и человек) |
| 3 | `llm` | сообщения | объект `AIMessage` |
| 4 | `parser` | `AIMessage` | строка `str` |

---

## 8. Разбор кода

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "Ты опытный Python-разработчик. Объясняй концепции кратко, ёмко и с одним примером кода."),
    ("human", "Что такое {topic} в контексте {domain} и зачем это нужно?")
])
parser = StrOutputParser()
chain = prompt | llm | parser
result = chain.invoke({"topic": "паттерн Singleton", "domain": "архитектуры ПО"})
```

| Фрагмент | Что происходит |
| :--- | :--- |
| `("system", "...")` | Реплика с ролью «система»: задаёт стиль ответа |
| `("human", "... {topic} ... {domain} ...")` | Реплика человека с двумя пропусками |
| `StrOutputParser()` | Превращает `AIMessage` в обычную строку |
| `prompt \| llm \| parser` | Соединяет три детали в конвейер |
| `chain.invoke({...})` | Подаёт словарь на вход и возвращает результат последней детали |

Что реально уходит модели после подстановки:

- Система: «Ты опытный Python-разработчик. Объясняй концепции кратко, ёмко и с одним примером кода.»
- Человек: «Что такое паттерн Singleton в контексте архитектуры ПО и зачем это нужно?»

## 9. Что ещё умеет цепочка (для самостоятельных опытов)

Этих примеров в файле `step1_lcel.py` нет. Добавьте их в конец скрипта и посмотрите, как ведёт себя цепочка.

Потоковый вывод — текст появляется по кусочкам, как в чате:

```python
for chunk in chain.stream({"topic": "декоратор", "domain": "Python"}):
    print(chunk, end="", flush=True)
```

Несколько запросов за один вызов:

```python
answers = chain.batch([
    {"topic": "декоратор", "domain": "Python"},
    {"topic": "генератор", "domain": "Python"},
])
```

Обратите внимание: цепочка осталась прежней, изменился только способ запуска. В этом и состоит смысл единого интерфейса.

## 11. Частые ошибки

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| Ошибка «не хватает переменных в шаблоне» | В словаре нет ключа, который есть в шаблоне, или опечатка в имени | Имена ключей должны совпадать с плейсхолдерами: `topic`, `domain` |
| Вместо текста в консоли длинный объект с метаданными | Забыли `StrOutputParser` в конце цепочки | Добавьте `\| parser` |
| Ошибка при вызове `chain.invoke("строка")` | Цепочка ждёт словарь, а передана строка | Передавайте `{"topic": "...", "domain": "..."}` |
| Шаблон «ломается» на фигурных скобках | В тексте промпта есть `{` или `}`, не относящиеся к плейсхолдерам | Удвойте скобки: `{{` и `}}` |

## 12. Проверь себя

<details>
<summary>1. Что произойдёт, если убрать `parser` из цепочки?</summary>

Цепочка вернёт объект `AIMessage`, а не строку.
</details>

<details>
<summary>2. Какого типа данные на выходе шаблона?</summary>

Готовый набор сообщений (система и человек), в который уже подставлены значения.
</details>

<details>
<summary>3. Чем цепочка из этого модуля похожа на команды в терминале Linux?</summary>

Результат левой части передаётся на вход правой, как в `cat файл \| grep слово \| sort`.
</details>

<details>
<summary>4. Зачем нужен единый интерфейс `Runnable`?</summary>

Любую деталь и любую цепочку запускают одинаково: `invoke`, `stream`, `batch`. Поэтому цепочки можно вкладывать друг в друга.
</details>

---

## 13. Что запомнить

- `|` соединяет детали в конвейер, выход левой детали — вход правой.
- На входе цепочки словарь, на выходе при `StrOutputParser` — строка.
- Имена ключей словаря должны совпадать с плейсхолдерами шаблона.
- Один и тот же `chain` можно запускать тремя способами: `invoke`, `stream`, `batch`.
